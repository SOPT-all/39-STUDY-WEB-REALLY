### 기다렸더니 대기 중이 -1? 무슨 일이세요

원래 코드는 `await` 뒤에서도 클릭 당시의 `pending`과 `completed`를 읽었음.
시간이 흘렀다고 같은 핸들러의 State가 최신 값으로 바뀌지는 않음.

세 setter에 업데이터 함수를 전달해 앞선 업데이트 결과로 계산하도록 수정했다.

**Hwang's 응용**  
구매 요청을 Real:ly PR 리뷰 요청으로 변경.  
3초 뒤 완료되는 동작은 타이머로 표현.

### 확인해보자

1. 처음에는 대기 `0`/ 완료 `0`.
2. 한 번 누르면 대기 `1` → 약 3초 뒤 대기 `0`/ 완료 `1`.
3. 새로고침하고 빠르게 세 번 누르면 대기 `3`.
4. 모두 처리되면 대기 `0`/ 완료 `3`.

대기 인원이 마이너스가 되는 스터디? 여기서는 해결.

## 2. 잘못된 State 업데이트 고치기

- [공식 챌린지](https://ko.react.dev/learn/updating-objects-in-state#challenges)
- [App.js](./02-updating-objects/App.js)

### 점수는 멈추고, 이름 바꾸니까 갑자기 따라옴

기존 `player.score++`는 State 객체를 직접 변경했다.  
이름 변경으로 리렌더링이 일어났을 때 뒤늦게 바뀐 점수가 표시될 수 있었던 것.

점수도 새 객체로 업데이트하고, 이름 수정시에도 기존 속성을 복사했다.  
특히 성만 전달해서 객체를 교체하면 이름과 점수가 사라질 수 있음. 전개 구문 확인 부탁.

**Hwang's 응용**  
플레이어를 HWANG으로, 점수를 리뷰 점수로 변경했다.

### 확인해보자

1. `+1`을 세 번 누르면 `10 → 13`.
2. 이름을 바꿔도 성과 점수는 유지.
3. 성을 바꿔도 이름과 점수는 유지.

이름 바꿨다고 리뷰 경력까지 초기화되면 곤란하니까 ^^

## 3. 장바구니의 항목 업데이트하기

- [공식 챌린지](https://ko.react.dev/learn/updating-arrays-in-state#challenges)
- [App.js](./03-updating-arrays/App.js)

### 배열도 새로, 바뀌는 상품도 새로

`map`으로 새 배열을 만들고, 선택한 상품은 전개 구문으로 새 객체를 만들었음.  
나머지 상품은 기존 객체를 그대로 반환한다.

**Hwang's 응용**  
상품을 Real:ly 스터디 간식으로 변경.  
수량 증가 로직은 공식 챌린지와 같다.

### 확인해보자

1. 초기 수량은 아메리카노 `1`/ 소금빵 `5`/ 초콜릿 `2`.
2. 아메리카노의 `+`를 두 번 누르면 아메리카노만 `3`.
3. 소금빵의 `+`를 누르면 소금빵만 `6`.
4. 다른 상품의 수량이 같이 바뀌지 않는지 확인.

간식 수량은 올렸고요. 실제 주문은 별개.
