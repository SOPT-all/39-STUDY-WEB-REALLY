## 🆙: 스터디 방식

- 매주 **발표자 2명**이 해당 주차 내용을 발표하고 실습을 준비합니다.
- 모든 스터디원은 **아티클(공부 기록)을 작성하고 PR로 제출**합니다.
- 스터디 전까지 **자신의 Real:ly 동지s아티클**에 배운 점, 질문, 피드백을 댓글로 남깁니다.
- **(심화/선택)** 해당 주차 개념의 예상 면접 질문과 답변을 작성합니다.

### 🌴: 브랜치 & PR Rules

- 최신 `main`에서 매주 새 브랜치를 만듭니다.
- 브랜치명: `주차/이름/주제` → `week1/yurim/ui`
- 주차는 `weekN` 형식/ 이름은 영문이름/ 주제는 학습 키워드로 간단명료하게 작성 Plz
- PR 제목: `[Week1] 유림 - UI 표현하기`
- PR 본문에 어떤 내용을 다뤘는지 간단히 작성해주세요.
- **정리 글 링크/ 실습 스크린샷**도 함께 첨부해주세요.
- PR은 `main`으로 보내고, 모임 이후 스터디장이 병합합니다.

### 📁: 폴더 구조

```text
39-STUDY-WEB-REALLY/
├── .github/
│   └── pull_request_template.md
├── docs/
│   └── yurim/week1/README.md
├── practice/
│   └── yurim/week1/
├── .gitignore
└── README.md
```

| 경로 | 용도 |
| --- | --- |
| `docs/이름/weekN/` | 각자 공부한 내용이나 아티클을 `.md` 파일로 기록 |
| `practice/이름/weekN/` | 실습을 준비한 사람이 실습 코드와 관련 자료를 업로드 |

- 파일은 **본인 디렉토리 아래에** 정리해주세요.
  예: `docs/yurim/week1/README.md`
- **Notion·블로그 링크로 제출해도 됩니다.** 다만, 기록이 남도록 `.md` 파일에 링크를 작성해주세요.
- **파일명과 하위 폴더 구조는 자유**입니다. 단, 반드시 **본인 디렉토리**에서 작업 Plz
